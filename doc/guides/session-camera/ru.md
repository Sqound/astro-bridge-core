## Сеансы и локальная история

Карточки подключённых приборов показывают включённые данные сеанса только для
чтения: операцию, цель, значения с единицами и возрастом. Через три периода источника
значение помечается как последнее показание. «Приостановлено» означает, что наблюдатель
уступил доступ, а не что прибор остановлен. Отсутствующие значения остаются
неизвестными. Выбирайте данные в каждом профиле. Для сложения кадров Seestar нужен
ключ владельца; его получение требует явного действия и Интернета на мосту.
Выбор чтения сохраняется при замене ключа. DWARF даёт только связь и допускает одно
приложение за раз.

Открыть сеанс показывает сохранённые графики, максимумы кадров, причины отклонения
и среду. Наблюдаемая выдержка суммирует лишь увиденные приросты принятых кадров при
неизменной выдержке кадра. Отсутствие исходных значений, изменения и сбросы делают
итог неполным; последняя выдержка кадра указана отдельно. Штриховка означает отсутствие
записанной загрузки исходных данных сопряжённым приложением, а не закрытое приложение.
Покрытие старых или укрупнённых журналов остаётся неизвестным. Непроверенные часы
дают приблизительное время; порядок последовательности сохраняется. Последние
события ограничены 500 показаниями и записями жизненного цикла. CSV/JSON включают
все сохранённые показания; JSON также включает события и имена читателей.
Настройки → Сеансы задают ночи и МиБ; действует первый достигнутый лимит. Уменьшение
лимитов может удалить старые данные. Удаление необратимо: сначала экспортируйте,
затем явно подтвердите. Только сопряжённые приложения с разрешением телеметрии или
администратора могут читать сеансы; эти права не управляют прибором. История хранится
локально даже без читающего приложения.

## Подключённые камеры и ограничения

Pi Zero W и Zero 2 W — только для соединений и телеметрии. Камерам нужен одобренный
класс Pi 3/4; начните физическую приёмку камер на стенде Pi 3B. В Настройки → Камеры
осознанно включите службу и обнаружение. Демо запускается без камер; кнопка добавляет
только локальный симулятор. Клиенты обнаруживают мост и запрашивают реальные точки
доступа для каждого соединения; вводить адрес прибора не нужно. Обнаружение Alpaca
отвечает только в подтверждённых сетях управления. Адрес появляется лишь после
успешного открытия слушателя.

Предоставляются только поддерживаемые физически подключённые камеры. UVC требует
поддерживаемых форматов и калибровки шага пикселя владельцем через
camera-calibration.json; редактора калибровки нет. Следуйте
процедуре владельца, сохраняйте другие записи, затем безопасно
переподключите камеру или перезапустите службу. ID по порту не доказывает физическую
идентичность. UVC снимает ограниченную яркость (GREY/Y16/YUYV), до 1280×960 с биннингом 1.
Длинные запросы усредняют кадры, а не дают настоящую непрерывную длинную экспозицию.
Без управления экспозицией длительность номинальная. Камера без затвора не создаёт
искусственные тёмные кадры. SDK производителей не включены; таким камерам нужен
установленный поддерживаемый драйвер. Большие передачи по 2.4 ГГц могут быть медленными.
Поддерживаемый биннинг 2 — лишь начальное значение; выбор приложений сохраняется.

Одновременно камерой владеет один клиент Alpaca. ClientID — номер протокола, а не
сопряжённое приложение; имя DHCP появляется только при точном актуальном совпадении
адреса. Разрешить этому приложению использовать камеру требует явного согласия на
освобождение показанного текущего владельца и может прервать экспозицию. Смена
владельца отменяет старое согласие. Другое приложение должно подключиться заново;
новый владелец автоматически не назначается. Повторные отключения предлагают
проверить кабель и концентратор с питанием, но не доказывают сбой напряжения.
Реальные камеры и телефоны, производительность Pi и ConformU остаются
**описанными, но не проверенными на оборудовании**; см. ограничения USB.
